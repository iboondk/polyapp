# ADR-0003: Generated types with openapi-typescript and a thin openapi-fetch runtime

- **Status:** Accepted
- **Date:** 2026-10

## Context

Each front end needs typed calls to the API, and the types must match the spec exactly. Heavy generators that need Java or emit large runtime code would slow every consumer.

## Decision

`openapi-typescript` generates `packages/api-client/src/generated/schema.d.ts` from the spec. The generated file is committed, so consumers do not need the codegen step. At runtime `openapi-fetch` makes the typed calls, and `createPolyAppClient()` adds a small facade with a `PolyAppError` type. `signWebhook()` is a helper for tests and the demo.

CI runs `pnpm gen` and then `git diff --exit-code` on the generated file, so any drift from the spec fails the build.

## Consequences

- Positive: types only at generation time, a tiny runtime, and no Java dependency.
- Negative: the committed file must be regenerated by hand when the spec changes. CI enforces this.
- Trade-off: the facade is thin on purpose. It does not add retries or caching.
